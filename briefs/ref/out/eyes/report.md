# Gate 的眼睛

[从入口体验](http://127.0.0.1:8740/start.html?lang=zh) · [语气关](http://127.0.0.1:8740/stage3.html?lang=zh) · [表情实验](http://127.0.0.1:8740/eyes-lab.html?eyes=doubt)

在入口按 `]` 可以排练到通行证。重新启动预览时，在项目目录运行 `python3 -m http.server 8740 --bind 127.0.0.1`。

## 表情和时刻

| 页面 | 触发 | 看得见的反应 |
| --- | --- | --- |
| start | 进入、打开勾选框、勾选成功 | 浅色背景里跟随指针；打开验证时收窄、看框；成功时慢眨并移开。 |
| face | 获取人脸、转头或数眨眼 | 有面部关键点时跟随镜像画面中的脸；测试开始时凑近。间隔太均匀、太随机或样本不足时，一高一低地看向读数再回看；第二次被拦时半闭。 |
| stage2 | 等待、准备选图、显示判定 | 指针进入选项、按下或键盘聚焦时审视。冷门选项、过于整齐的节奏、超时后被放行时看判定区。速度越界被拦时移开视线。 |
| stage3 | 进入、录音、判定 | 白底下方升起直角矩形光场，两条眼睛在光里变清楚。录音时收窄，声压同时驱动眼睑、光和声波。被拦时眼睛压扁、转红，约 480 ms 后卡片升起。离开前转绿、慢眨。 |
| jury | 判断卡片、答错、获担保 | 入场即疑惑；选中卡片时看向证词，稍停再回看。答错转冷，判断正确或三人担保后慢眨。 |
| pass | 出示通行证 | 眼睛回到背景，慢眨一次后看向侧面，停在那里。 |

## 动作来源和视觉调整

观察了 Jérémy Perret 的 bloub（MIT，版本 b4bb3c1）。face.ts 把眼睑开度和视线分开，闭眼比睁眼略快；gaze.ts 把指针归一化后再限制偏转。Gate 的 CSS 圆头条、表情参数和时间曲线是本地实现，未复制上游代码或图形。这里把日常眨眼放慢到 400 ms，约 7 秒一次；疑惑看向数据约 1.15 秒，再回到最新的追踪目标。[眼睛和眨眼源码](https://github.com/jeremy-prt/bloub/blob/b4bb3c1/src/bot/face.ts) · [指针源码](https://github.com/jeremy-prt/bloub/blob/b4bb3c1/src/ui/gaze.ts) · [MIT 许可证](https://github.com/jeremy-prt/bloub/blob/b4bb3c1/LICENSE)

1. 对照旧光球截图与 voice-ref-sheet，先把深色退到底部。第一轮录音截图暴露了旧状态文字与声波重叠，随后把停顿说明独立放到胶囊下方。
2. 对照 bloub 的半闭轮廓和四张 375px 截图，加深下半屏的光，让浮现的白眼有足够衬底；拦截时改为暗红色扁眼。两条目标刻度从语气文字所在的同一行向外展开。
3. 按最新反馈把椭圆光场换成直角矩形。手机两侧留 4% 白边，顶边有很薄的光晕。实验页同步使用矩形。陪审页把背景眼睛抬到标题上方，以适应同时更新的标题文案。

## 验收

375 × 812 的 Chrome 浏览器从 start 逐页按 `]` 到 pass。六页和实验页切换期间监听了控制台错误及未捕获异常。实验页另测了强制疑惑、模拟向左注视、音量滑块和减少动态效果；桌面 1280 × 800 检查了录音键与横向溢出。

录音截图使用 Chrome 的测试音频设备，把含有停顿的 WAV 输入页面原有的麦克风分析器，实际经过音量测量、停顿提交、两次判定和进入陪审页。第二轮显示当次实测值，42% 是文案示例。测量的是原型定义的音量和时长指标。

## 还差什么

- 真人脸追踪接的是现有关键点。此次验收用浏览器测试设备，真人移动、真实手机摄像头和现场麦克风的体感还未验证。
- 为保留原来的两轮流程，第一轮“再念一次”会开启第二轮录音；第二轮同名按钮触发原有的放行并进入陪审。这里保留了一处文案与动作的差异。
